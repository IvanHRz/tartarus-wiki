# Release v0.6.2 — Multi-tenancy MSSP (Flocks completo)

> Rango: `6f584b7`..`0085c31` (v0.5.0 → v0.6.2). Mergeado en **PR #8**; pin de Beelzebub v3.8.0
> en **PR #9**. Es el salto de plataforma mono-tenant a **consola de dos niveles multi-cliente**.

## Qué cambió y por qué importa

- **Multi-tenancy "Flocks" completo (Fases 3–5).** `flock_id` (nullable, `NULL = Default`) recorre
  eventos, detecciones, kill-chain, sesiones, honey-creds, hosts y sensores. Un operador MSSP puede
  aislar por cliente/segmento sin backfill destructivo. Ver [[0002-multi-tenancy-flocks]].
- **RBAC de 3 roles** (global_admin / manager / watcher), fail-closed. Un Manager del Cliente A no
  ve nada del B. Ver [[0003-rbac-tres-roles]].
- **Consola de dos niveles:** vista madre (agrega cross-flock) vs workspace de flock (todo
  scopeado). Ver [[0006-consola-dos-niveles]].
- **Acknowledge (limpieza de ruido estilo Thinkst):** ocultar-sin-borrar; los reportes ven el 100%.
  Ver [[0004-acknowledge-limpieza-de-ruido]].
- **Attack Map con contexto de despliegue** (interno/externo, MITRE, host:puerto). Ver
  [[0005-attack-map-contexto-de-despliegue]].
- **Beelzebub fijado a v3.8.0** (antes `:latest`, no reproducible).

## Problemas conocidos abiertos (heredados a v0.6.3)

- **#10 — ingesta AMQP ciega** (bloqueante de despliegue). Detección + auto-reconexión añadidas
  2026-08-07, verificación E2E pendiente. Ver [[2026-08-07-ingesta-amqp-ciega]].
- **#11 — `honeypot_id` siempre NULL** (consumer lee `HandlerName`, Beelzebub emite `Handler` vacío)
  → el attack-map mapea por protocolo, no por sensor real.
- **Telemetría de campo rota** — `/events/webhook` no existe; el sensor RPi no reporta. Bloquea
  despliegue self-service (Tier E). Ver [[deploy-checklist]].

## Estado de tests
824+ tests unit/mock verdes. **Aún sin test de integración de aislamiento entre flocks** (el aporte
más sensible de esta release no se prueba contra Postgres real) — es gate T0-3.
