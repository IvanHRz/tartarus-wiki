# Plan — Telnet nativo + HTTPS/TLS nativo (habilitados por Beelzebub v3.9.0)

## Context

El upgrade a Beelzebub v3.9.0 desbloqueó **telnet nativo** y **TLS/HTTPS nativo**; el usuario eligió
construir ambos (son config, no build, y cierran dos huecos de cobertura). **Telnet nativo** cierra el
hallazgo del análisis (`docs/ANALISIS_TELNET.md`): hoy el honeypot de :23 habla SSH y **no captura telnet
crudo/IoT (Mirai)**. **HTTPS nativo** cierra el hueco del estudio (`docs/ESTUDIO_HTTPS_TLS.md`): el :8443
está mapeado sin servicio (cobertura falsa) y da paridad con Thinkst.

Hallazgos verificados (schema embebido en el binario v3.9.0 + config local):
- **Protocolo `telnet` es nativo** (enum `["ssh","http","tcp","telnet","mcp"]`) y comparte struct con los
  demás → soporta `commands` + `plugin` → el telnet nativo puede llevar **LLM Cisco + respaldo estático +
  guardrails** (lo que ya tenemos en `telnet-23.yaml`).
- **TLS = `tlsCertPath` + `tlsKeyPath`** (rutas a archivos, ambos obligatorios; Go verifica existencia al
  arrancar). Los configs se montan read-only en `/configurations` (`docker-compose.yml:15`) → el cert va en
  `beelzebub/configurations/certs/` y se referencia como `/configurations/certs/...`.
- **:443** ya está mapeado en `docker-compose.dev-mac.yml:7` (`8443:443`) pero NO en el compose base ni en
  el contenedor actual → añadirlo al base como puerto de honeypot de primera clase.
- **consumer** (`consumer.py`): `_PORT_PROTOCOL_MAP` ya mapea `23→TELNET`; deriva `dest_port` del
  `ServerAddr`. Los eventos de :443 quedarán como `HTTP` con `dest_port=443` (aceptable; etiqueta HTTPS
  explícita queda como follow-up opcional, sin tocar el pipeline ahora).

## Decisiones (tomadas, alineadas con el alcance)
1. **Convertir :23 a telnet nativo** (`protocol: ssh` → `protocol: telnet`), conservando el CLI Cisco por
   LLM + respaldo estático + guardrails. El puerto telnet ahora habla telnet (lo correcto). Se pierde el
   acceso por SSH al Cisco (workaround previo); si más adelante se quiere, se añade un Cisco-SSH en otro
   puerto. `:22` (Ubuntu SSH) no se toca.
2. **HTTPS con certificado autofirmado** (configurable: la ruta permite sustituirlo por uno de CA real),
   sirviendo el mismo portal que `http-80`. Autofirmado es lo estándar para un honeypot.
3. **:443 como puerto de honeypot de primera clase** en el compose base.

## Pasos

### A. Telnet nativo (`beelzebub/configurations/services/telnet-23.yaml`, gitignored)
- Cambiar `protocol: "ssh"` → `protocol: "telnet"`. Mantener `commands` (handlers Cisco estáticos + catch-all
  `plugin: LLMHoneypot`), `serverVersion`, `passwordRegex`, bloque `plugin` (LLM + prompt con guardrails).
- Restart Beelzebub. **Verificar**: `telnet`/`nc localhost 2323` → login + `show version` (estático) +
  comando raro (LLM) + intento de jailbreak (guardrail sigue en personaje); eventos llegan como **TELNET**.
  (El test por SSH ya no aplica: ahora es telnet de verdad.)
- Si el LLM no se comporta bien sobre telnet nativo → dejar telnet estático (aún captura y responde a los
  top) y anotar; no bloquea.

### B. HTTPS/TLS nativo
- **Certificado autofirmado:** generar `cert.pem`/`key.pem` en `beelzebub/configurations/certs/` (CN
  plausible, p.ej. el hostname interno). `openssl req -x509 -newkey rsa:2048 -nodes -days 825 …`.
- **Servicio nuevo** `beelzebub/configurations/services/https-443.yaml` (gitignored): `protocol: "http"`,
  `address: ":443"`, `tlsCertPath: /configurations/certs/cert.pem`, `tlsKeyPath: /configurations/certs/key.pem`,
  `commands` = clon del portal de `http-80.yaml` (mismo contenido, ahora sobre TLS).
- **Puerto:** añadir `- "${HTTPS_PORT:-8443}:443"` a los `ports` de beelzebub en `docker-compose.yml` (base).
- Recreate beelzebub (con el mapeo :443). **Verificar**: `curl -k https://localhost:8443/` → 200 con el
  portal; handshake TLS OK con el cert; el evento aterriza (protocol HTTP, `dest_port=443`).

### C. Higiene + scripts + ejemplos
- **`.gitignore`:** añadir `beelzebub/configurations/certs/` (la clave privada nunca se versiona).
- **`scripts/attack_all.py::attack_telnet`:** ahora que :23 es telnet nativo, volver a ataque telnet crudo
  (socket/`nc`-style, como el original) en vez de SSH; verificar que produce eventos TELNET. `attack_https`
  ya apunta a :8443 (ahora sí responde) — verificar.
- **`beelzebub/configurations/services.example/`** (tracked): actualizar `telnet-23.yaml` a `protocol: telnet`

  versionado y el CI/otros lo vean. `scripts/validate_beelzebub.py` ya valida protocol/address/commands (no
  requiere cambio; telnet/https siguen teniendo esos campos).

# Plan — G-4: proveedor/key LLM por honeypot desde la UI (+ sacar la key del YAML manual)

## Context

El usuario eligió G-4 de la épica Beelzebub: poder **elegir el proveedor de IA (OpenAI/DeepSeek/OpenRouter/
Ollama) y su key POR honeypot desde la consola**, sin editar YAML a mano. Arregla el bug conocido: hoy
`POST /settings/beelzebub/ai` escribe `.env` pero **Beelzebub no lo lee** (no-op); y habilita el ahorro
(DeepSeek/Ollama) y sacar la key del YAML manual → gestión desde la UI.

Hallazgos verificados (factibilidad confirmada):
- **El engine SÍ puede escribir los YAML de Beelzebub:** monta `./beelzebub/configurations` en
  `/app/bee-config` **rw** (`docker-compose.dev-mac.yml:21`), y `TARTARUS_SERVICES_DIR=/app/bee-config/services`
  (dev-mac:30) → el mismo dir que Beelzebub lee en `/configurations:ro`. Escritura confirmada (ESCRIBIBLE).
  ⚠️ Ese mount vive en dev-mac; **prod no lo tiene** → añadirlo a `docker-compose.prod.yml` (o documentar).
- **`personality_engine` ya escribe** los YAML con `yaml.safe_dump` (`:349`) en `apply` (persona), y
  **protege** `_PROTECTED_PLUGIN_KEYS = (openAISecretKey, host, llmModel, llmProvider)` (`:52`). G-4 hace lo
  **opuesto**: una función que ESCRIBE esos campos. Reusa el mismo load/dump (data preservada; comentarios se
  pierden, igual que apply — aceptable).
- **`services_router.GET /services`** ya reporta `llm: {backed(bool), provider, model}` y **nunca** la key
  (`:77-81`). El nuevo `POST` solo escribe; jamás devuelve la key (C5).
- **UI:** el modal `#serviceConfigModal` (index.html) ya tiene meta + persona + `scLlmInfo` (muestra
  provider/model actuales) + botones. Se le añade una sección "Proveedor LLM". `openServiceConfig` (main.js)
  ya carga el servicio y muestra el LLM.
- **Restart:** C4 (el engine no reinicia contenedores) → el endpoint devuelve `restart_required` + comando;
  la UI muestra el banner de reinicio (igual que `applyPersonaToService` hoy).
- **Enum de proveedor Beelzebub:** `openai | ollama`. DeepSeek/OpenRouter = `provider: openai` + `host`
  (API OpenAI-compatible). Ollama = `provider: ollama` + `host`.

## Backend

### 1. `personality_engine.set_llm(file, provider, model, host, api_key, services_dir=None) -> dict`
- Carga el YAML del servicio (helper existente). **Requiere** que ya tenga bloque `plugin` (servicio
  LLM-backed); si no, 400 ("habilita LLM aplicando una persona con bloque LLM" — enable-on-static queda fuera).
- Actualiza `config["plugin"]`: `llmProvider`, `llmModel`; `host` si se provee (si vacío → quitar, para
  volver a OpenAI directo); `openAISecretKey` **solo si `api_key` viene** (si vacío → conserva la actual, no
  la borra). Preserva `commands` (handlers estáticos) y `prompt`.
- Escribe con `safe_dump` (mismo patrón que `apply`). Devuelve `{provider, model, host}` — **NUNCA la key**.
  Jamás loguea la key (enmascarar).

### 2. `services_router.POST /services/{file}/llm`
- Valida que `file` es un servicio conocido. Body `{provider, model, host?, api_key?}`. Valida
  `provider ∈ {openai, ollama}`. Llama `set_llm`.
- Devuelve `{file, provider, model, host, restart_required: true, restart_command: "docker restart tartarus-beelzebub"}`.
  Nunca la key. Enmascarar en logs.
- **`POST /settings/beelzebub/ai`** (el no-op): añadir en su respuesta una nota de **deprecado** →
  "usa POST /services/{file}/llm" (no romper; solo señalar).

## UI (`ui/src/index.html` + `ui/src/js/main.js`)
- En `#serviceConfigModal`, añadir (visible solo si `svc.llm.backed`) una sección **"Proveedor LLM"**:
  - **Proveedor** (select): OpenAI · DeepSeek · OpenRouter · Ollama (local).
  - **Modelo** (input, autocompletado por preset, editable).
  - **Host** (input; autocompletado por preset para DeepSeek/OpenRouter/Ollama; oculto/vacío para OpenAI).
  - **API key** (input password, write-only; placeholder "•••• (sin cambios)"; vacío = conservar la actual).
  - Botón **"Guardar proveedor LLM"** → `POST /services/{file}/llm` → banner "reinicia Beelzebub".
- **Presets** (JS): DeepSeek→`{provider:openai, host:https://api.deepseek.com/v1/chat/completions, model:deepseek-chat}`;
  OpenRouter→`{provider:openai, host:https://openrouter.ai/api/v1/chat/completions}`;
  Ollama→`{provider:ollama, host:http://ollama:11434/api/chat}`; OpenAI→`{provider:openai, host:""}`.
- `openServiceConfig`: prellenar proveedor/modelo desde `svc.llm`. La key nunca se prellena.
